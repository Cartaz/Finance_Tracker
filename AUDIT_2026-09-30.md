# Finance Tracker audit — 30 September 2026

Audited production baseline: `9d084ee00941bdc74cff9d2544083ba5520267d5` (`main`). The open Q1 preview at `1ae4564123cfcf0856f24e0e1a9b02341bc5626c` was inspected and its three QML tests executed separately. This audit fixes production defects; it does not claim to finish the QML migration or certify a V1 release.

## Inventory and scope

Reviewed repository instructions, installation/CI, settings and XDG paths, database lifecycle/schema v9, ledger/posting/tracking policies, accounts/categories/payees, historical FX, reporting, budgets, recurrence/forecast, loans/rate revisions/custom payments, CSV staging/reconciliation, transport, backup/restore, native window/Qt worker ownership and the frontend modules. Core tests cover cross-book references, rollback, monetary magnitudes, storage limits, rounding, recurrence anchors, budget overlap, loan amortization and migration semantics. Existing intentional domain behavior and the schema are preserved.

The full production frontend is WebEngine/QWebChannel. The user-requested Qt Quick architecture remains the target, but the open preview only displays read-only dashboard data. Replacing production with it now would remove implemented workflows. No QML cutover or release tag is part of this corrective audit.

## Reproduced defects and corrections

| Severity | Finding | Correction and evidence |
| --- | --- | --- |
| P0 | If the first `live.replace(rollback)` failed, restore recovery moved the still-original live file to `failed`, reopened a newly created empty database, then deleted the original. | Explicit ownership of the original-moved transition; checkpoint/close/sidecar failures are inside recovery; recovery never quarantines an unmoved original. Failure injection covers checkpoint, sidecar deletion, first rename, staged rename and reopen. The original book and SQLite integrity remain intact. |
| P1 | CSV parsing/staging ran on the GUI thread; reading and rendering every imported row amplified GUI work. | Production frontend calls `startCsvImport`; the worker has its own SQLite connection. The existing owned persistence-task lifecycle serializes CSV and backup/restore, blocks mutation during maintenance and protects close. Backend pagination and 100 visible rows bound frontend work. A 10,000-row Qt test observes GUI timer heartbeats and validates pagination/mutation blocking. |
| P1 | `AppStateService` retained a `CurrencyRegistry` attached to the connection closed by restore. | Resolve the registry from the current `Database.connection` on each metadata request. Close/reopen regression confirms currency metadata remains accessible. |
| P1 | Eight public money fields were not in the explicit transport vocabulary, risking JavaScript integer rounding above `2^53`. | Register assets, liabilities, savings, opening/ending balances, ending base value and entry quantity/value fields. Each is tested with `2^53 + 1`; all cross the boundary as exact text. |
| P1 | Rows without external IDs could link the same account transaction multiple times. | Candidate exclusion now also considers resolved staging rows for the same book/account. A second link is refused. |
| P1 | Reconciliation compared individual entries rather than the transaction's net native quantity on the imported account. | Group account entries by transaction and compare their sum in both candidate and persisted-identity compatibility checks. Split-entry regression accepts the net amount and refuses a partial amount. |
| P2 | Merging a payee archived the source but left recurring templates pointing to it, causing future posting/forecast validation to fail. | Repoint scheduled payee references in the same merge transaction. Regression posts a schedule successfully to the surviving payee. |
| P2 | Compact ISO dates were accepted then persisted verbatim; SQL date ranges could omit those transactions. Offset times could mix aware and naive local times. | Canonicalize stored account/transaction dates and times; reject offset times before persistence. Compact-date reporting and offset refusal regressions pass. |
| P2 | Payload conversion happened outside the bridge error boundary; IDs/intervals accepted truncated floats. `error_payload` re-raised type/value failures caught by the bridge. | Validate object payloads inside the boundary, require exact integer types/text and boolean flags, bound IDs to SQLite range, and return explicit validation errors. |
| P2 | Invalid UTF-8 settings could break startup; invalid locale values could be accepted. | Diagnose encoding failures and malformed types; fall back to code defaults. Tests cover damaged encoding and invalid types. |
| P2 | CSV excess columns could be silently discarded; malformed structures were not consistently classified. | Strict CSV parsing, explicit column-count validation, BOM handling and early row limit enforcement. Invalid input is refused without partially staged rows. |
| P2 | The native page allowed arbitrary local navigation by URL scheme. | Confine file resources to the frontend root, allow only the WebChannel resource and `about:blank`, block other embedded resources, and open external HTTP(S) only for main-frame navigation. |

SQLite snapshot targets are restricted to owner-only access before data is copied, including restore staging files. Temporary cleanup failures are logged; recovery failures preserve rollback evidence and the verified safety snapshot.

## Explicit remaining gates

The container has no usable OpenGL compositor. The offscreen window screenshot was blank despite successful DOM/backend execution, and starting Xvfb failed because listening sockets are unavailable. Pixel/layout verification, real keyboard/focus/HiDPI behavior, native file dialogs and CachyOS/KDE Wayland integration therefore remain unverified. Domain/DOM execution does not prove those visual/native gates. QML screen parity and the eventual removal of WebEngine also remain unfinished. Do not infer a production release certification from this audit.

## Mandatory strategic review

Outcome for this corrective milestone: **STRATEGIC AFTER CLEANUP**. Release/QML cutover remains **BLOCKED** by the explicit gates above.

1. **Sources of truth:** SQLite/domain owners remain canonical; CSV worker uses the same reconciliation rules and does not add a second ledger writer.
2. **Duplication:** Import preparation uses one argument contract and one domain implementation. Scheduling, tracking, FX and amortization remain in existing policy owners.
3. **Information leakage:** The native bridge validates transport only; Python owns persistence and filesystem policy. The frontend receives bounded rows and exact financial text.
4. **Module depth:** Reuse the existing owned task lifecycle instead of introducing an independent CSV pool/maintenance gate. Its historic `BackupTaskManager` name is documented; its broader persistence responsibility is intentional.
5. **Layering:** No SQL or financial arithmetic moved into UI or controller. Controller only composes isolated worker services and delegates.
6. **Nearby cases:** Import handles both review modes, limit failures and paged reconciliation. Restore handles failures before and after the original-file transition.
7. **Errors:** Explicit validation envelopes; unexpected failures are logged and sanitized. Recovery retains evidence when rollback cannot reopen.
8. **Atomicity:** Ledger/staging writes remain transactional; payee merge updates history and future templates atomically. Restore cannot discard an original that failed to move.
9. **Concurrency/lifecycle:** Worker connections are owned/closed by workers, GUI read snapshots are released before import, maintenance excludes mutations and close waits for owned persistence work.
10. **Regression protection:** Permanent failure-injection, precision, connection-reopen, reconciliation, worker-heartbeat and real frontend tests protect the repaired behavior.
11. **Complexity budget:** Bounded paging and shared maintenance replace unbounded UI work and independent concurrency concerns. No speculative framework was introduced.
12. **Cleanup:** Invalid boundary coercions, stale currency connection, incomplete transport vocabulary and future payee references were repaired in their owning layers.
